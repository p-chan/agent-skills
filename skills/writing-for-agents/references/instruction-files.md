# 指示ファイル固有のルール

文書が `AGENTS.md` や `CLAUDE.md` などの指示ファイルのときに、[`SKILL.md`](../SKILL.md) の原則に加えて判断することを定める。

指示ファイルは、セッションの開始時に自動で読み込まれる。どの作業でも読み込まれるので、指示ファイルは最もコンテキストの負荷が大きい置き場である。10回に1回しか使わない情報は、残りの9回も負荷を払う。長くなると指示に従う精度が下がり、重要なルールが埋もれる。短く正確な指示ファイルは、曖昧なルールが並ぶ長い指示ファイルより役に立つ。

指示ファイルは強制力のある設定ではなく、エージェントが従おうとする文脈である。例外なく守らせる必要がある処理は、hook、lint、CI などで機械的に強制する。

## 書く情報

指示ファイルには、そのファイルの適用範囲のほぼすべての作業で必要になり、エージェントが推測できない情報を書く。

| 書く                                        | 書かない                                                   |
| ------------------------------------------- | ---------------------------------------------------------- |
| 推測できないビルド、テスト、lint のコマンド | コードを読めば分かること                                   |
| ツールの既定と異なる規約                    | 言語の標準的な規約など、エージェントがすでに知っていること |
| ブランチ名、コミット、PR の慣習             | 詳細な API ドキュメント（参照を書く）                      |
| プロジェクト固有の設計判断とその理由        | 頻繁に変わる情報                                           |
| 開発環境の癖（必要な環境変数など）          | 長い説明やチュートリアル                                   |
| 繰り返し発生する落とし穴                    | ファイルごとの説明                                         |
| 完了の定義と、作業を検証する方法            | 「きれいなコードを書く」のような自明な指示                 |

ディレクトリ構成やアーキテクチャの概要は、コードから分かる範囲では書かない。重要なディレクトリの役割や、エージェントが読みすぎるときにどこを優先して読むかなど、コードから分からないことだけを書く。

## 情報の置き場

情報は、適用範囲に応じて置く。

| 適用範囲                           | 置き場                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------- |
| リポジトリのほぼすべての作業       | ルートの指示ファイル                                                      |
| 特定のディレクトリやファイル       | そのディレクトリの指示ファイル、パスで範囲を限定したルール                |
| 特定の作業、複数手順の作業         | Skill                                                                     |
| 詳細な設計や仕様                   | `docs/` などの文書                                                        |
| 例外なく守らせるルール             | hook、lint、型検査、CI                                                    |
| 自分だけの好み（口調、詳しさなど） | ユーザー単位の指示ファイル（`~/.codex/AGENTS.md`、`~/.claude/CLAUDE.md`） |

プロジェクト固有であることは、ルートの指示ファイルに置く理由にならない。リポジトリの指示ファイルには、チームとコードベースのルールを書く。

ファイルを分けても、起動時に読み込まれるなら負荷は減らない。Claude Code の `@path` によるインポートは、整理には役立つが起動時にすべて読み込まれる。負荷を減らすには、パスで範囲を限定したルール、Skill、条件付きの参照を使う。

## 詳細な情報への参照

指示ファイルには、詳細な情報そのものではなく、それを読む条件と参照先を書く。

悪い例:

```md
作業前に `docs/` 以下をすべて読む。
```

良い例:

```md
DB スキーマを変更するときは `docs/database.md` を参照する。
```

## 読み込みの仕組み

どの指示ファイルがどの順で読み込まれるかは、エージェントによって違う。2026-09-27 時点の公式ドキュメントでは次のとおり。

| 項目         | Codex                                                        | Claude Code                                                                                                      |
| ------------ | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 読み込む範囲 | プロジェクトのルートから作業ディレクトリまでの各ディレクトリ | 作業ディレクトリとその上位の各ディレクトリ。下位のディレクトリのファイルは、そこのファイルを読んだときに読み込む |
| 優先         | 作業ディレクトリに近いファイルが後に連結され、優先される     | 作業ディレクトリに近いファイルが後に連結される                                                                   |
| 大きさの目安 | 合計 32 KiB（既定）を超えると以降を読み込まない              | 1ファイル200行以下を推奨                                                                                         |

Claude Code は、既定では `CLAUDE.md` がないときだけ `AGENTS.md` を読む。両方のエージェントで同じ指示を使うときは、`AGENTS.md` を正本にし、`CLAUDE.md` に `@AGENTS.md` を書いて読み込む。Claude Code 固有の指示は、その下に書く。

## 確認項目

指示ファイルの編集やレビューでは、[`SKILL.md`](../SKILL.md) の確認項目に加えて、次を確認する。

- 適用範囲のほぼすべての作業で必要か
- より限定された指示ファイル、Skill、文書へ移せないか
- 機械的な強制に置き換えられないか
