# 指示ファイル固有のルール

文書が `AGENTS.md` や `CLAUDE.md` などの指示ファイルのときに、[`SKILL.md`](../SKILL.md) の原則に加えて判断することを定める。

指示ファイルは、そのファイルが適用される範囲の作業で、条件なく読み込まれる。どの作業でも読み込まれるので、指示ファイルは最もコンテキストの負荷が大きい置き場である。10回に1回しか使わない情報は、残りの9回も負荷を払う。

## 書く情報

指示ファイルには、そのファイルの適用範囲のほぼすべての作業で必要になる、環境から分からない安定した情報を書く。

情報を追加する前に、次を確認する。

- 適用範囲のほぼすべての作業で必要か
- 知らないと誤った判断をしやすいか
- より限定された置き場に置けないか

## 情報の置き場

情報は、適用範囲に応じて置く。

| 適用範囲                     | 置き場                                                         |
| ---------------------------- | -------------------------------------------------------------- |
| リポジトリのほぼすべての作業 | ルートの指示ファイル                                           |
| 特定の作業                   | Skill                                                          |
| 特定のディレクトリ           | そのディレクトリに近い指示ファイル、パスで範囲を限定したルール |
| 詳細な設計や仕様             | `docs/` などの文書                                             |
| 機械的に検証できるルール     | lint、テスト、hook、CI                                         |

プロジェクト固有であることは、ルートの指示ファイルに置く理由にならない。

アーキテクチャや設計は、指示ファイルに概要と参照だけを書き、詳細は文書に置く。

## 詳細な情報への参照

指示ファイルには、詳細な情報そのものではなく、それを読む条件と参照先を書く。

悪い例:

```md
作業前に `docs/` 以下をすべて読む。
```

良い例:

```md
DB スキーマを変更するときは `docs/database.md` を参照する。
```

## 確認項目

指示ファイルの編集やレビューでは、[`SKILL.md`](../SKILL.md) の確認項目に加えて、次を確認する。

- より限定された指示ファイル、Skill、文書へ移せないか
- 機械的な検証に置き換えられないか
