# Skill 固有のルール

文書が Skill のときに、[`SKILL.md`](../SKILL.md) の原則に加えて判断することを定める。frontmatter、呼び出し方の選択、呼び出しでの分割、ルーター Skill を扱う。

## 呼び出し方

Skill の呼び出し方には2つの選択肢があり、それぞれ異なる負荷を払う。

| 呼び出し方         | 呼び出せる主体                 | 払う負荷           |
| ------------------ | ------------------------------ | ------------------ |
| モデルが呼び出す   | エージェント、他の Skill、人間 | コンテキストの負荷 |
| 人間だけが呼び出す | 人間                           | 認知の負荷         |

エージェントが自分で呼び出す必要がある場合か、他の Skill から呼び出す必要がある場合に限り、モデルが呼び出す Skill にする。人間が手動でしか呼び出さないなら、人間だけが呼び出す Skill にして、コンテキストの負荷を払わない。

### モデルが呼び出す Skill

`description` を持ち、エージェントが自律的に呼び出せる。他の Skill からも呼び出せ、人間も名前を入力して呼び出せる。

`description` は Skill の最上位の参照で、常にコンテキストに読み込まれる。発見されやすさと引き換えに、コンテキストの負荷を払い続ける。

参照情報だけを持つモデルが呼び出す Skill は、複数の Skill が共有する参照情報の置き場にもなる。他の Skill から呼び出せるので、共有する参照情報を1箇所に置ける。

frontmatter では `disable-model-invocation` を省略する。`description` はモデル向けに、呼び出す分岐を書く。[`SKILL.md`](../SKILL.md) の参照の書き方がすべて当てはまる。

悪い例:

```yaml
description: Pull Request に関する Skill。
```

良い例:

```yaml
description: Pull Request を作成・更新・レビューするときに使う。
```

### 人間だけが呼び出す Skill

エージェントからは `description` が見えず、人間が名前を入力したときだけ呼び出される。他の Skill からは呼び出せない。コンテキストの負荷はないが、人間がその Skill の存在を覚えておく認知の負荷を払う。

frontmatter で `disable-model-invocation: true` を指定する。`description` は人間向けの1行の要約にして、呼び出す分岐は書かない。

人間だけが呼び出す2つの Skill が共有する参照情報は、どちらの Skill にも置けない。互いに呼び出せないからである。Skill の外にある通常のファイルに置き、どちらの Skill からも参照する。

## 呼び出しでの分割

手順列での分割は [`SKILL.md`](../SKILL.md) で扱う。ここでは呼び出しでの分割を扱う。

次のどちらかに当てはまる場合に、モデルが呼び出す Skill を分割する。

- 独立して呼び出すべき、固有の中心となる語がある。実際にプロンプトで使っている語であること
- 他の Skill から、その部分だけを呼び出す必要がある

分割すると、新しい `description` のコンテキストの負荷を常に払う。独立して呼び出せることに、その負荷に見合う価値がある場合だけ分割する。

一部の分岐だけで必要な参照情報を分けたいだけなら、新しい Skill にせず、同じ Skill の参照ファイルへ移す。

## ルーター Skill

人間だけが呼び出す Skill が増えて覚えきれなくなったら、ルーター Skill を作る。ルーター Skill は、人間だけが呼び出す1つの Skill で、他の Skill の名前と、それぞれを使う場面を並べる。人間は多くの Skill の代わりに、ルーター Skill だけを覚えればよい。

ルーター Skill は他の Skill を案内するだけで、呼び出すことはできない。人間だけが呼び出す Skill は、人間にしか呼び出せないからである。

## 確認項目

Skill の編集やレビューでは、[`SKILL.md`](../SKILL.md) の確認項目に加えて、次を確認する。

- 呼び出し方が、呼び出す必要のある主体に合っているか
- `description` に、同じ分岐の言い換えや、本文が伝えている説明が増えていないか
- 他の Skill と責務が重複していないか
