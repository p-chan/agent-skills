# Skill を書くとき

文書が Skill のときに、[`SKILL.md`](../SKILL.md) の原則に加えて判断することをまとめる。

Skill は段階的に読み込まれる。エージェントは最初にすべての Skill の `name` と `description` だけを読み、使うと決めたときに `SKILL.md` の本文を読む。参照ファイルやスクリプトは、必要になったときに初めて読んだり実行したりする。

## 1つの Skill が受け持つ範囲

1つの Skill には1つの仕事だけを持たせる。同じプロンプトを何度も使っている作業や、同じ訂正を何度もしている作業が、Skill にする候補になる。

最初からすべての例外に対応しようとしない。代表的な作業を1つ選んで確実に動くようにし、使いながら範囲を広げる。

## description の書き方

`description` はその Skill への入り口になる参照で、エージェントはこれを見て Skill を使うかどうかを決める。[`SKILL.md`](../SKILL.md) の参照の書き方は、すべて `description` にも当てはまる。

- 何をする Skill かと、いつ使うかの両方を書く
- ユーザーが実際に使う言葉を入れる
- 主な用途を先頭に置く。Skill が多いと、`description` は途中で切り詰められる

悪い例:

```yaml
description: Pull Request に関する Skill。
```

良い例:

```yaml
description: Pull Request の本文を書く。Pull Request を作成、更新するときに使う。
```

`name` は、同じリポジトリにある既存の Skill の命名に揃える。`helper` や `utils` のような、何をするのか分からない名前は避ける。

## 誰が呼び出すか

Skill の呼び出し方は2通りあり、どちらを選ぶかで増える負荷が変わる。

| 呼び出し方               | 呼び出せる相手                   | 増える負荷         |
| ------------------------ | -------------------------------- | ------------------ |
| エージェントも呼び出せる | エージェント、ほかの Skill、人間 | コンテキストの負荷 |
| 人間だけが呼び出せる     | 人間                             | 認知の負荷         |

エージェントが自分の判断で呼び出す必要があるか、ほかの Skill から呼び出す必要があるときだけ、エージェントも呼び出せる Skill にする。人間が手で呼び出すだけなら、人間だけが呼び出せる Skill にして、コンテキストの負荷をなくす。デプロイやメッセージ送信のように副作用があり、実行のタイミングを人間が決めたい作業も、人間だけが呼び出せる Skill にする。

### エージェントも呼び出せる Skill

`description` が常にコンテキストに読み込まれ、エージェントが自分の判断で呼び出せる。人間も名前を入力して呼び出せる。見つけてもらいやすい代わりに、コンテキストの負荷がずっとかかる。

参照情報だけを持つ Skill にしておけば、複数の Skill が共通で使う参照情報の置き場にもなる。

### 人間だけが呼び出せる Skill

エージェントは自動で呼び出さず、人間が名前を入力したときだけ呼び出される。コンテキストの負荷はかからないが、人間がその Skill の存在を覚えておく必要がある。

設定の仕方はエージェントによって違う。

- Claude Code：frontmatter に `disable-model-invocation: true` を書く。`description` はコンテキストに読み込まれなくなる
- Codex：`agents/openai.yaml` に `policy.allow_implicit_invocation: false` を書く

人間だけが呼び出せる2つの Skill で参照情報を共有したいときは、どちらの Skill にも置けない。互いに呼び出せないからである。Skill の外に普通のファイルとして置き、両方の Skill から参照する。

## 本文と参照ファイル

`SKILL.md` の本文は500行以内に収め、それに近づいたら詳細を参照ファイルに移す。本文は一度読み込まれると以降の会話に残り続け、毎ターンのコストになる。作業全体を通して守らせたいことは、一度きりの手順ではなく、常に守るルールとして書く。

参照ファイルは `SKILL.md` から直接参照し、参照ファイルからさらに別のファイルを参照させない。参照を何段もたどらせると、エージェントがファイルの一部しか読まないことがある。100行を超える参照ファイルには、先頭に目次を置く。

毎回確実に同じ結果を得たい処理や、外部のツールが必要な処理に限って、スクリプトを同梱する。それ以外は文章で指示する。

## 呼び出し方で分けるとき

手順の区切りで分けることは [`SKILL.md`](../SKILL.md) で扱っている。ここでは呼び出し方で分けることを扱う。

エージェントも呼び出せる Skill は、次のどちらかに当てはまるときに分ける。

- その部分だけを呼び出すためのキーワードがあり、実際にそのキーワードをプロンプトで使っている
- ほかの Skill から、その部分だけを呼び出す必要がある

分けると、新しい `description` の分だけコンテキストの負荷がずっとかかる。単独で呼び出せることに、それだけの価値があるときだけ分ける。

一部のケースでしか使わない参照情報を切り出したいだけなら、新しい Skill にはせず、同じ Skill の参照ファイルに移す。

## 案内役の Skill

人間だけが呼び出せる Skill が増えて覚えきれなくなったら、案内役の Skill を作る。案内役の Skill は人間だけが呼び出せる Skill で、ほかの Skill の名前と、それぞれを使う場面を並べる。人間は、たくさんの Skill の代わりに案内役の Skill だけを覚えればよくなる。

案内役の Skill はほかの Skill を案内するだけで、代わりに呼び出すことはできない。人間だけが呼び出せる Skill は、人間にしか呼び出せないからである。

## 呼び出されるかの確かめ方

想定される依頼をいくつか用意し、`description` のとおりに Skill が呼び出されるかを確かめる。呼び出されないときは、ユーザーが使う言葉が `description` に入っているかを見直す。呼び出されすぎるときは、`description` をもっと具体的にするか、人間だけが呼び出せる Skill にする。

## 確認項目

Skill の編集やレビューでは、[`SKILL.md`](../SKILL.md) の確認項目に加えて、次を確かめる。

- 1つの仕事に絞られているか
- 呼び出し方が、呼び出す必要がある相手と、副作用の有無に合っているか
- `description` に何をするかといつ使うかが書かれていて、同じケースの言い換えや、本文を読めば分かる説明が混ざっていないか
- 参照ファイルが `SKILL.md` から直接参照されているか
- ほかの Skill と役割が重なっていないか
