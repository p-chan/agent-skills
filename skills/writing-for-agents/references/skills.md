# Skill 固有のルール

文書が Skill のときに、[`SKILL.md`](../SKILL.md) の原則に加えて判断することを定める。

Skill は段階的に読み込まれる。エージェントは最初に全 Skill の `name` と `description` だけを読み、使うと判断したときに `SKILL.md` の本文を読み、必要になったときに参照ファイルを読むかスクリプトを実行する。

## 責務

1つの Skill には1つの仕事を持たせる。同じプロンプトを繰り返し使う作業や、同じ訂正を繰り返す作業が、Skill にする候補である。

最初から全ての例外に対応しようとしない。代表的な作業を1つ選んで動くようにし、使いながら広げる。

## description

`description` は Skill の最上位の参照で、エージェントはこれを見て Skill を使うか判断する。[`SKILL.md`](../SKILL.md) の参照の書き方がすべて当てはまる。

- 何をする Skill かと、いつ使うかの両方を書く
- ユーザーが実際に使う語を含める
- 主な用途を先頭に置く。Skill が多いと `description` は切り詰められる

悪い例:

```yaml
description: Pull Request に関する Skill。
```

良い例:

```yaml
description: Pull Request の本文を書く。Pull Request を作成・更新するときに使う。
```

`name` は、同じリポジトリの既存の Skill と同じ命名規則に揃える。`helper` や `utils` のような曖昧な名前は避ける。

## 呼び出し方

Skill の呼び出し方には2つの選択肢があり、それぞれ異なる負荷を払う。

| 呼び出し方         | 呼び出せる主体                 | 払う負荷           |
| ------------------ | ------------------------------ | ------------------ |
| モデルが呼び出す   | エージェント、他の Skill、人間 | コンテキストの負荷 |
| 人間だけが呼び出す | 人間                           | 認知の負荷         |

エージェントが自分で呼び出す必要がある場合か、他の Skill から呼び出す必要がある場合に限り、モデルが呼び出す Skill にする。人間が手動でしか呼び出さないなら、人間だけが呼び出す Skill にして、コンテキストの負荷を払わない。デプロイやメッセージ送信のように副作用があり、実行の時機を人間が決めたい作業も、人間だけが呼び出す Skill にする。

### モデルが呼び出す Skill

`description` が常にコンテキストに読み込まれ、エージェントが自律的に呼び出せる。人間も名前を入力して呼び出せる。発見されやすさと引き換えに、コンテキストの負荷を払い続ける。

参照情報だけを持つモデルが呼び出す Skill は、複数の Skill が共有する参照情報の置き場にもなる。

### 人間だけが呼び出す Skill

エージェントは自動で呼び出さず、人間が名前を入力したときだけ呼び出される。コンテキストの負荷はないが、人間がその Skill の存在を覚えておく認知の負荷を払う。

指定方法はエージェントによって違う。

- Claude Code: frontmatter で `disable-model-invocation: true` を指定する。`description` はコンテキストに読み込まれない
- Codex: `agents/openai.yaml` で `policy.allow_implicit_invocation: false` を指定する

人間だけが呼び出す2つの Skill が共有する参照情報は、どちらの Skill にも置けない。互いに呼び出せないからである。Skill の外にある通常のファイルに置き、どちらの Skill からも参照する。

## 本文と参照ファイル

`SKILL.md` の本文は500行以下に保ち、近づいたら詳細を参照ファイルへ移す。本文を読み込むと、その内容は以降の会話に残り続け、毎ターンのコストになる。作業全体に適用する指示は、一度だけ実行する手順ではなく、常に守るルールとして書く。

参照ファイルは `SKILL.md` から直接参照し、参照ファイルからさらに別のファイルを参照させない。入れ子の参照先は、エージェントが一部しか読まないことがある。100行を超える参照ファイルには、冒頭に目次を置く。

同じ結果を毎回確実に得たい処理や、外部ツールが必要な処理に限り、スクリプトを同梱する。それ以外は文章の指示で書く。

## 呼び出しでの分割

手順列での分割は [`SKILL.md`](../SKILL.md) で扱う。ここでは呼び出しでの分割を扱う。

次のどちらかに当てはまる場合に、モデルが呼び出す Skill を分割する。

- 独立して呼び出すべき、固有の中心となる語がある。実際にプロンプトで使っている語であること
- 他の Skill から、その部分だけを呼び出す必要がある

分割すると、新しい `description` のコンテキストの負荷を常に払う。独立して呼び出せることに、その負荷に見合う価値がある場合だけ分割する。

一部の分岐だけで必要な参照情報を分けたいだけなら、新しい Skill にせず、同じ Skill の参照ファイルへ移す。

## ルーター Skill

人間だけが呼び出す Skill が増えて覚えきれなくなったら、ルーター Skill を作る。ルーター Skill は、人間だけが呼び出す1つの Skill で、他の Skill の名前と、それぞれを使う場面を並べる。人間は多くの Skill の代わりに、ルーター Skill だけを覚えればよい。

ルーター Skill は他の Skill を案内するだけで、呼び出すことはできない。人間だけが呼び出す Skill は、人間にしか呼び出せないからである。

## 検証

想定する依頼をいくつか用意し、`description` によって期待どおりに呼び出されるかを確かめる。呼び出されないときは、ユーザーが使う語が `description` にあるかを確認する。呼び出されすぎるときは、`description` を具体的にするか、人間だけが呼び出す Skill にする。

## 確認項目

Skill の編集やレビューでは、[`SKILL.md`](../SKILL.md) の確認項目に加えて、次を確認する。

- 1つの仕事に絞られているか
- 呼び出し方が、呼び出す必要のある主体と副作用の有無に合っているか
- `description` に、何をするかといつ使うかがあり、同じ分岐の言い換えや本文が伝えている説明が増えていないか
- 参照ファイルが `SKILL.md` から直接参照されているか
- 他の Skill と責務が重複していないか
