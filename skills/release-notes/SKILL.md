# リリースノート

変更内容の説明を、ユーザー視点で何が変わったのか分かるように書く。

- 変更の主題を1文で書く
- 主題から逸れる補足は書かない。主題が機能追加なら付随するオプション名などは書かず、主題がオプション追加ならオプション名を書く
- 辞書形か体言止めで書く（`Add`、「追加する」、「追加」）

## 例

### 機能追加

NG: 過去形で、補足が多い

```text
--format オプションと --output オプションを追加した
```

OK

```text
CSV エクスポート機能を追加する
```

### バグ修正

NG: 実装視点で、過去形

```text
リストが空の場合の null チェックを追加した
```

OK

```text
空のリストを渡したときにクラッシュする問題を修正する
```

### 破壊的変更

NG: 過去形で、補足が多い

```text
createUser 関数のシグネチャを変更しました。第2引数以降を options オブジェクトにまとめました
```

OK

```text
`createUser` の引数を options オブジェクト形式に変更する
```
